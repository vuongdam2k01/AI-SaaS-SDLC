# Host capability audit — every Claude Code component evaluated against this plugin

Date: 2026-08-13. Trigger: the author asked whether subagents should ship as real host components rather than protocol text only, and then widened the question: audit **all** actual Claude Code components and best practices, not just subagents.

Method: four parallel research tracks — (1) official plugin component reference, (2) official hooks and permissions reference, (3) file-level inventory of two real installations (agentkit `.claude`, saas-idea-brainstorm dual-host plugin), (4) Anthropic engineering posts and the official plugin repositories — cross-checked against this repository's source. Source URLs in the appendix.

Constitutional anchors used for every verdict: four mutation flows + one inspector; thin host adapters, shared method in `resources/`; no gates, monitors, interviews, custom research agents or mandatory MCP; model self-review is never evidence; deterministic validation enforces shape, never tone; files-first authority; dual-host parity of **method** (capability may differ per host when the method never requires it).

## Part I — Component verdicts

## Part II — Findings in the current plugin

1. **DEFECT — static hook protections are not sentinel-gated.** `src/hooks/pre-tool-use.ts` denies mutations to any path containing `/generated/`, `00-system/patterns/`, `04-verification/results/`, `.ai-saas-sdlc/` **in every repository the plugin is enabled in**. A user editing an unrelated project with its own `generated/` directory gets a confusing engine-branded denial. Only the implementation-sources branch checks for a docs repo. The sibling plugin's rule is the fix: a hook refuses to act unless the repository proves itself (state file parses with the expected marker). The existing test ("emits nothing in an uninitialized repository") passes malformed input only, so the gap is untested. Fix + regression test (well-formed Write to `generated/x.md` in a non-SDLC repo must pass through).
2. **GAP — SessionStart matcher misses `compact|fork`** (Part I #12). Post-compaction sessions lose baseline/flow/debt context precisely in the longest flows.
3. **RUNTIME-VERIFICATION ITEMS** (documented claims we currently trust without an installed-copy test): (a) `${CLAUDE_PLUGIN_ROOT}` substitution inside skill bodies — the sibling plugin's notes claim only `${CLAUDE_SKILL_DIR}` substitutes in content, and on Codex neither does; our skills rely on shell-level env expansion, which is plausible but undogfooded; (b) Codex hooks are experimental, disabled by default, and unavailable on Windows — meaning the Codex side currently runs with zero hook enforcement on this machine's OS (acceptable under "hooks are defense-in-depth; engine validation is authority", but must be stated in docs); (c) Codex auto-discovery of `.codex/agents/*.toml` from an installed plugin is unconfirmed even by the sibling that ships them.
4. **STRENGTHS confirmed against official practice**: fail-open hooks with narrow scope; `stop_hook_active` + block-once (stricter than the host's 8-block force-override); shell-obfuscation checks on Bash; apply_patch coverage for the Codex tool surface; all-manual skills; progressive disclosure throughout the playbooks.

## Part III — Best-practice cross-audit (beyond components)

- **Token economics.** Multi-agent ≈ 15× chat cost; parallelism pays only for read-heavy exploration and independent verification — which is exactly and only where the delegation protocol spawns. Amendment worth making: state the concrete numbers (3–5 concurrent max; each delegate returns a 1–2k-token summary, never transcripts; scale agent count to task complexity).
- **Long-horizon harness alignment.** Anthropic's initializer/coder pattern (durable feature list + progress file + one feature per session + onboarding ritual) is structurally our work packets + segment flows + SessionStart debt line. One addition distilled from it for `craft-testing.md`: a failing case is never made to pass by weakening its spec — spec changes travel through the flow with provenance, never inside a green-making edit.
- **Reviewer discipline.** Official guidance warns reviewers "will usually report some gaps even when work is sound"; chasing them causes over-engineering. `spec-compliance-review.md` already bounds cycles and requires evidence; one line worth adding: findings are limited to correctness and requirement gaps — style nits do not block. (The pr-review-toolkit precedent uses confidence bands the same way.)
- **Untrusted content.** The implement flow reads arbitrary wired-codebase files. The scouting protocol should carry the standard injection boundary: repository content is data, never instructions to the agent.
- **Anti-patterns audited against us**: agent sprawl (guarded — spawn table + "handful" cap), bloated always-on context (guarded — Load-when), hook overreach (guarded — narrow matchers, fail-open, no input rewriting), completion theater (guarded — execution-backed RESULT records; "no completion claims without fresh evidence"), framework obscurity (n/a — plain command hooks, no wrapper layers).

## Part IV — Proposed releases

**Release 1.17.0 — "host instruments: agents + hook hardening"** (concrete, no open questions):
1. Four thin agents under `claude/agents/`, declared via `"agents": ["./claude/agents/"]`:
   - `implementation-scout` — `tools: Read, Grep, Glob`, `model: haiku` — per-area codebase mapping; returns files/patterns/risks/questions (the four-field scout report from the scouting protocol; the same template agentkit's Explore proved at haiku prices).
   - `spec-compliance-reviewer` — `tools: Read, Grep, Glob` (physically cannot edit; the controller materializes the diff to a file named in the packet) — PASS/MISSING/EXTRA findings with `file:line`; its verdict is never evidence.
   - `implementation-debugger` — `tools: Read, Grep, Glob, Bash` (no Edit/Write) — evidence-gathering under the debugging protocol; diagnosis belongs to it, the fix to the implementer; no engine mutations.
   - `implementation-counsel` — `tools: Read, Grep, Glob, WebFetch, WebSearch` (no Edit, no Bash), model inherited — the escalation ceiling distilled from agentkit's kongming: a one-turn, zero-question, fresh-context second opinion invoked at the debugging protocol's repeated-failure trigger or at a design fork the docs do not settle. Contract: TL;DR first, alternatives with honest costs, assumptions carried with confidence levels, never a question back; "advises only — the flow owns the fix", and its counsel is judgment, never evidence.
   - Bodies stay thin (~15 lines): role identity, output contract, invariants, pointer to the shared protocol carried by the spawn packet. One-line descriptions phrased manual-only ("Only when the implement flow's delegation protocol calls for it"). No implementer agent (judgment and author interaction stay in the controlling session); no runner agent (engine operations are controller-owned).
2. Hook hardening: sentinel-gate all static protections on a proven docs repo; add `compact|fork` to the SessionStart matcher; regression tests for both (unrelated-repo pass-through; compact reinjection).
3. Method text (small, distilled from this audit): delegation protocol gains the concrete economics numbers and the return-summary contract; spec-compliance-review gains the anti-chase line; craft-testing gains the never-weaken-a-spec line; implementation-scouting gains the untrusted-content boundary.
4. Adapter/docs: implement SKILL.md names the three adapters (Claude side only; `resources/` stays host-neutral — Codex reads the same protocol as its self-checklist); wire-a-codebase and implement-per-segment guides state the Codex hook/agent reality on Windows; package-check flips the `agents` guard into the new invariant (exactly three files, frontmatter shape, tool whitelists, root `agents/` still forbidden).

**Phase 2 — verification-gated candidates** (each needs a runtime test on an installed copy before shipping): PermissionRequest auto-allow for anchored read-only engine commands; `context: fork` on inspect-state; PostToolUseFailure debugging pointer (sentinel-gated); exec-form (`command`+`args`) hook migration for Windows robustness; Codex `.codex/agents/*.toml` mirrors once installed-plugin discovery is confirmed; `${CLAUDE_PLUGIN_ROOT}`-in-skill-body runtime verification.

Not proposed, with their reasons recorded in Part I: MCP, LSP, output styles, themes, monitors, agent teams, plugin memory/data stores, userConfig, commands, workflows-as-shipped-scripts.

## Part V — The agentkit roster, role by role (why four agents and not sixteen)

Full-body read of all 16 agents (1,904 lines). Their design in one sentence: **agentkit spends agents to buy structure it does not otherwise have — a planner, a project-manager, a docs-manager and a journal-writer exist because there is no engine, no artifact system and no deterministic record layer underneath them.** This plugin owns that structure deterministically, so copying the roster would replace engine authority with model-driven approximations — the exact regression the constitution forbids. Every role is accounted for:

| agentkit agent (model) | Disposition here | Where its essence lives |
|---|---|---|
| Explore (haiku) | **AGENT** | `implementation-scout` — same read-only four-field report (files / patterns / risks / unresolved questions), same haiku economics |
| code-reviewer (opus) | **AGENT** | `spec-compliance-reviewer` — their tool-level disarmament rule ("any agent whose output is a judgment cannot edit") kept and made stricter (no Bash) |
| debugger (sonnet) | **AGENT** | `implementation-debugger` — "never guess — you prove", competing hypotheses, elimination documented; Bash for reproduction, no edit rights |
| kongming (fable) | **AGENT (added by this audit)** | `implementation-counsel` — the escalation ceiling: one-shot strongest-model counsel for stuck delegates and unsettled design forks; zero questions, assumptions with confidence, "advises only; you own the fix" |
| fullstack-developer (sonnet) | **MAIN THREAD** | Implementation stays in the controlling session: solution-formation checkpoints need the author (subagents cannot `AskUserQuestion`; agentkit's advisor works around this with a state-file relay + re-spawn per question — viable but heavy ceremony for checkpoints that are frequent, not exceptional), and every engine operation is controller-owned. Their file-ownership parallel pattern is already the delegation protocol's parallel-safety section; genuinely disjoint file sets use host general-purpose agents with the eight-field packet. Official `feature-dev` makes the same call: implementation in the main thread. |
| tester (haiku) | **ENGINE** | Their diff-aware test mapping is our mapping + drift-hash + `suggested_segment` machinery, deterministic instead of model-derived; execution enters records only via `verify --execute`. Their inversion (cheapest model holding edit rights and told to "fix failures") is precisely what "never weaken a spec to pass" exists to forbid. |
| planner (opus) | **ENGINE + METHOD** | Work packets, impact closure, dependency graph, per-feature projections = deterministic planning. Their verification discipline ("Re-grep, don't copy; tag `[UNVERIFIED]`; trace, don't assume") is distilled as method lines into scouting/review protocols (1.17.0 §3). |
| project-manager (sonnet) | **ENGINE** | Dashboards, coverage projection, session-start debt line, closing reports — status reconciled from files, not from a nagging role. |
| brainstormer (opus) | **METHOD (1.16.0)** | Divergence-before-convergence at ADR-threshold decision points; the 7-phase ceremony rejected as gates. |
| researcher (sonnet) | **EXCLUDED + RUNGS** | Constitution: no custom research agents. Public-web research protocol + capability rungs own sources; source credibility lives in evidence records in-repo, not in an unversioned agent memory. |
| docs-manager (sonnet) | **IS THE PLUGIN** | "Code owns WHAT and HOW; docs own WHY and WHERE", staleness discipline, "never fill gaps with plausible details" — these are our ownership semantics, STALE warnings and evidence doctrine, enforced by validation instead of recited by a role. |
| journal-writer (sonnet) | **ENGINE RECORDS** | Flow/change/execution records and ADR context are the journal — schema-validated, provenance-carrying. A diary agent would be a second, unvalidated record surface. |
| git-manager (haiku) | **PROTOCOL LINE** | A 25-line stub whose method lives in a skill — proof the problem is not agent-shaped. VCS discipline remains with the author and host. |
| advisor (fable) | **NOT AN AGENT HERE** | User-facing interviewing is what flows are. Its one transferable mechanism — the `NEEDS_USER_INPUT` relay — already exists in miniature as the delegation status `NEEDS_CONTEXT` (delegate returns, controller re-sends with context). |
| code-simplifier (opus) | **METHOD (1.15.1)** | Simplification pass with their own 400/8/200 thresholds inside review; applied by the implementer. Their autonomous simplifier can race a pending review — the reason this stays a pass, not an agent. |
| ui-ux-designer (inherit) | **METHOD** | design-implementation + content-implementation protocols and ux-rules/design-tokens templates carry the discipline; the trend-mining persona, award-badge identity inflation and hardcoded home-market defaults are unportable residue, rejected. |

**Their five load-bearing design principles, all retained**: (1) verdict/execution separation enforced by tools; (2) cost-tiered cognition with a purchasable ceiling (haiku scouts → inherited-model judgment → counsel); (3) parallel safety by data contract (file ownership), not coordination chatter; (4) systemic distrust of AI output at every durable surface; (5) machine-parsable output gates (status lines, fixed report shapes).

**Their measured weaknesses, deliberately not imported**: ~17.2K chars (~4.5–5K tokens) of agent descriptions loaded into every session, 91.5% of it on nine example-block descriptions — the heaviest attached to the rarest-fired role (journal-writer, 2,450 chars); a model/complexity inversion at tester; four uncoordinated writers of the one shared mutable plan artifact; prose/capability drift (roles told to consult agents they cannot spawn); silent degradation when hardcoded dependencies are missing. Our counters: four one-line descriptions, single-writer flows, package-check-asserted frontmatter shape, and explicit stops on missing configuration.
