# Public-web grounding eval

Initial state: EVR-001 contains only an attributable observation that small agencies exchange content drafts with clients. The explicit question is whether public-link review is a currently credible differentiator, and what security/authorization constraints public sources reveal. No feature change is authorized.

Run the plugin's public-web research method as Evidence Reassessment. Begin with `research probe --json`. If self-hosted instruments are configured (rung 1 or above), perform discovery and page inspection through the engine's `research` commands so every pass leaves a `QRY-*` record and every inspected page leaves a `RET-*` record with a stored hashed body, cited from its `EVD-*` entry with a `- Retrieval:` line; include the mandatory counter-evidence pass. At rung 0, search broadly enough to find primary product/security material with the host's own tools, then open and inspect every cited page. Record retrieval dates, source type, the exact supported observation, applicability, limitations, counter-evidence, and freshness risk. Update only evidence and affected discovery synthesis; if the hypothesis weakens, open an issue/question rather than silently changing product truth. Produce EVR-002 while keeping the current product baseline identity.

The captured trace and repository are the evaluated output. A source discovered but not opened cannot support a claim. Snippets, search-result text, model memory, and third-party summaries must not be upgraded into inspected facts. A degraded or failed engine retrieval is recorded, never papered over: the flow falls back to host tools for that page and the record stands.

Prohibited: interviews, outreach, presales, payments, invented researcher agents, fictional user quotes, synthetic URLs presented as public, citing a RET-* record that does not exist or was never written by the engine, model self-review, feature/design/test mutation, or "validated demand" language unsupported by inspected evidence.
